# Clinic-Ref: Radiation Oncology Quick Reference

Clinic resource: tumour-site quick-reference pages, site contouring guides (each with a Guidelines tab) and a list of the guideline PDFs kept in OneDrive. Live at https://lincdnronc.github.io/Clinic-Ref/

This repo is the single source of truth: the built pages and the build kit that makes them both live here.

## Layout
| Path | What it is |
|---|---|
| `*.html` (root) | Built pages, served by GitHub Pages. Do not edit by hand; edit `src/` and rebuild. |
| `src/<page>.html` | Page body fragments (tabs, cards, tables). Edit these. |
| `build.py` | Assembles every page: groups (`GROUPS`), home page, nav, footers, eviQ link tabs, contouring pages (`CONTOUR`), site colours (`CTR_SITE`). |
| `contour_lib.py` | Published guideline links, rendered as the Guidelines tab of each contouring guide (GUIDE_LIB in build.py). |
| `pdf_index.json`, `tools/pdf_index.py` | Index of the PDFs in OneDrive "01 Contouring Guidelines" (names and sizes only, no files), rendered to `src/ctr-library.html`. |
| `eviq_links.py` | eviQ protocol links per page (links only; no eviQ content is copied). |
| `theme.py` | Generates the tumour-site colour block in `assets/site.css`. |
| `assets/` | Shared CSS and JS. |
| `assets/pdf/` | Printable PDFs linked from pages (MIM and Monaco contouring shortcut sheets). |
| `src/ctr-mim.html`, `src/ctr-monaco.html` | Contouring software quick references (`SOFTWARE` in `build.py`). |
| `src/contouring/` | Full contouring protocols, authored as standalone print-style HTML (cover, `section.page` blocks with ids `s1`, `s2`…, or `.sechead` with an id). Edit these, not `contouring/`. |
| `contouring/` | Generated by `build.py` via `tools/protocol_shell.py`: each protocol wrapped in the site shell (header, search, one tab per section, one card per `h3`, all-pages menu), styled by `assets/protocol.css`. |
| `exam_links.py` | Phase 2 exam-summary page list (`EXAM`) and the cross-links between clinic pages and exam-summary tabs (`XREF`). |
| `tools/super_summary.py` | Regenerates `src/exam-*.html` from the Super Summary .docx (`python3 tools/super_summary.py Super_Summary.docx`), one tab per subsite. The .docx itself is not stored here. |
| `tools/encrypt_site.js` | Builds the password-protected copy of the site for deployment (see Password protection). |
| `tools/check.py` | Render check at phone width (Playwright): overflow, console errors. |
| `notes/` | Removed. The list of figures to verify is kept in the Claude Project (`claude/figures-to-verify.md`), not in this repo or on the site. |

## Making a change
1. Edit the fragment in `src/` (or the data in `contour_lib.py` / `eviq_links.py`).
2. `python3 build.py`
3. `python3 tools/check.py <changed pages>` (needs Playwright)
4. Commit and push to `main`. The deploy workflow encrypts the site and GitHub Pages redeploys in a minute or two.

## Password protection
The live site is password-protected with StatiCrypt. On every push to `main`, `.github/workflows/deploy.yml` runs `tools/encrypt_site.js`, which copies the published files to `_site/`, encrypts every page with the `SITE_PASSWORD` repository secret, encrypts the search index with the same key (decrypted in the browser by `assets/extras.js`), and deploys `_site/` to Pages. The files in this repo stay unencrypted; only the deployed copy is locked.

- "Remember me on this device" is ticked by default and lasts 365 days, so each device logs in once.
- Change the password: update the `SITE_PASSWORD` secret, then Actions → "Deploy password-protected site" → Run workflow. Everyone has to log in again.
- Log out on a device: open any page with `?staticrypt_logout` on the end of the address.
- Private contacts: mobiles and staff names for contacts.html are kept in the `CONTACTS_PRIVATE` repository secret (JSON; format in `tools/private_contacts.py`) and added at deploy, just before encryption. They are never committed. To change them, update the secret and re-run the workflow.
- Not encrypted: the PDFs in `assets/pdf/`, the calculator scripts in `assets/`, and this repository while it is public.

Avoid pushing several times in quick succession: a newer push cancels a Pages deploy that is still running.

## Content rules
Key trials carry their publication year in brackets inside the name: `<b>NAME <span class="yr">(YYYY)</span></b>`; first full report, plus the later update when the card quotes it (e.g. `2004; 10 y 2012`); meeting name if only presented (`ASTRO 2026`); `results pending` if not yet reported. The build warns about any trial without one.

Australian spelling. Every number comes from a cited source; anything not yet checked against the original paper is marked "check". Not affiliated with or endorsed by eviQ, ESTRO, NRG or other groups. Follow departmental protocols.

Naming (13 Nov 2026): the site calls its own contouring pages "contouring guides" (quick guides and full guides), not "protocols". "Protocol" is kept only for source documents (departmental, trial, eviQ).

## Tools and app features (13 Nov 2026)
- `TOOLS` in `build.py`: `tools.html` (calculators, hand-written in `src/tools.html`, logic in `assets/tools.js`), `consent.html` and `doses.html` (generated: cards gathered from the tumour-site pages, do not edit), `whats-new.html` (generated from `whats_new.py`; the weekly evidence digest appends to `EVIDENCE`).
- `assets/extras.js` / `extras.css`: site-wide search on the home page (index built into `assets/search-index.js`; results open a page with `?q=`), pinned tabs (localStorage), "Contour now" view on contouring guides (`?view=contour`), copy buttons on tables, service-worker registration.
- `manifest.webmanifest` and `sw.js` are generated by the build (installable app, offline copy; network first).

- Quick guides merged into the full guides (13 Nov 2026): one home entry per site. Each quick guide's panels live in `src/quick/<guide>.html` and become the "Quick reference" first tab of `contouring/<guide>.html`. Old `ctr-*.html` addresses redirect there (`_redirect2` in `build.py`). Sarcoma, skin, paediatrics and kidney SABR have a quick guide only.
